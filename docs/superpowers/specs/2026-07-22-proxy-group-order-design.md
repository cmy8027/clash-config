# 代理组前置排序设计

## 目标

调整 Clash Party 的 `GLOBAL` 选项中策略组的展示顺序：从截图红框中的 `HK香港` 开始，把地区组和指定服务组前置；截图中位于其前面的超时节点本次不处理。

本次只调整策略组顺序，不隐藏或删除超时节点，也不改变代理节点、规则匹配、代理组类型、测速地址或策略组之间的引用关系。

## 目标顺序

1. 地区策略组：按照脚本动态生成的地区组顺序，从 `HK香港` 开始；不存在的地区组自动跳过。
2. `其他节点`：存在时紧跟地区组之后，且只出现一次。
3. 截图红框中的服务策略组，按照当前脚本生成顺序排列：
   `国外AI`、`YouTube`、`Pixiv`、`游戏专用`、`跟踪分析`、`广告过滤`、`谷歌服务`、`微软服务`、`Github`、`日本网站`、`下载软件`、`其他外网`。
4. 其余策略组保留在后面，包括 `全部节点`、`默认节点`、`AI默认节点` 以及未启用或未列入前置清单的策略组。

## 实现方式

在 `main(config)` 完成所有策略组生成后，对 `config['proxy-groups']` 做一次稳定重排：

- 通过策略组名称建立前置名称集合；
- 先从现有数组提取命中的策略组，并保持地区组和服务组的指定顺序；
- 再追加未命中的策略组；
- 只重排数组，不复制或修改策略组对象，因此现有 `proxies` 引用和配置字段保持不变。

地区组和服务组都是动态生成的，重排逻辑只处理实际存在的对象；订阅节点变化或服务开关变化不会造成无效名称。

## 边界与错误处理

- `HK香港` 不存在时，从实际生成的第一个地区组开始前置。
- `其他节点` 不存在时跳过。
- 服务组未启用或未生成时跳过。
- 不重复添加任何策略组。
- 不改变 `config.proxies`，因此本次不会隐藏超时节点。

## 验证

- 使用 `node --check clash_override.js` 验证脚本语法。
- 使用 `git diff --check` 验证无空白错误。
- 用最小 mock 配置执行覆写逻辑，确认前置数组顺序、缺失组跳过和无重复。
- 检查现有规则和代理组引用仍指向原策略组名称。
